# Major Prompts Used

This document documents the major prompts used in the implementation of task tracker extended features. The source of this Markdown file is the attached ./report/Malda_Tabbah_SU25-26_MidCourse_Project.pdf

## Prompt Register


| #   | Major Prompt                                     | AI Tool / Model Used              | Key Prompt Instructions                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --- | ------------------------------------------------ | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Prompt for Creating User Stories                 | ChatGPT Pro / GPT 5.5             | Act as a senior product owner. Generate 3–4 user stories for due date, due date change date, overdue logic, and filtering/search. Use “team member” as the main role. Include 4–5 specific and testable acceptance criteria. Stay within the stated scope and return a table with ID, Story, Acceptance Criteria, and Notes/Assumptions.                                                                                                                  |
| 2   | Review of AI-Generated User Stories              | Human review after AI response    | Inspect AI-generated stories and update any requirement that does not match the intended business rule.                                                                                                                                                                                                                                                                                                                                                   |
| 3   | Prompt for Generating User Stories Documentation | ChatGPT Pro / GPT 5.5             | Act as a technical product owner. Create `docs/user_stories.md`. Do not generate new user stories. Use only the reviewed stories. Preserve IDs, wording, acceptance criteria, and notes as much as possible. Improve only Markdown structure, formatting, numbering, and readability.                                                                                                                                                                     |
| 4   | Prompt for Creating a Mini-ADR                   | ChatGPT Pro / GPT 5.5             | Act as a technical product owner and software architect. Review the original Task Tracker ADR and generate a mini-ADR with the same headings. Indicate what changes are needed and whether the existing architecture still fits. Keep the project simple, retain Python/FastAPI/Pydantic, keep the existing architecture where possible, and avoid authentication, multi-tenancy, microservices, Docker, cloud deployment, and production database setup. |
| 5   | Prompt for Comparing Original ADR and Mini-ADR   | ChatGPT Pro / GPT 5.5             | Compare the two documents and identify functional and technical specification differences. Do not compare word by word. Present the result in table form.                                                                                                                                                                                                                                                                                                 |
| 6   | Prompt for Generating Mini-ADR Documentation     | Not explicitly stated             | Create a Markdown file in the project `docs` folder using the reviewed and approved mini-ADR text.                                                                                                                                                                                                                                                                                                                                                        |
| 7   | Prompt for Backend Implementation Plan           | Cursor IDE / Cursor Grok 4.6 High | Act as a senior Python backend engineer. Review `@docs/user_stories.md`, `@docs/mini-adr.md`, `@backend/app/main.py`, and `@backend/app/models.py`. Generate a backend-only implementation plan. Do not apply code changes yet. Present the changes as a list of tasks in table form.                                                                                                                                                                     |
| 8   | Weak Prompt for Backend Testing                  | Not explicitly stated             | “I want to test all the backend points and make sure all user stories acceptance criteria are met. Please prepare the test script.”                                                                                                                                                                                                                                                                                                                       |
| 9   | Prompt for Manual Verification Using Curl        | Not explicitly stated             | Act as a senior backend tester. Generate curl commands to verify all acceptance criteria listed in `@docs/user_stories.md`. Do not run the curl tests. Let the user execute them one by one. Output a table with user story ID, acceptance criteria, curl command, and expected response.                                                                                                                                                                 |
| 10  | Follow-up Prompt for Running Backend Tests       | Not explicitly stated             | Run the selected test files one by one, log the result of each test, and write the results in `docs/verification.md`. Output the test results in table form.                                                                                                                                                                                                                                                                                              |
| 11  | Prompt for Frontend Implementation Plan          | Cursor IDE / Cursor Grok 4.6 High | Act as a senior Python frontend engineer. Review `@docs/user_stories.md`, `@docs/mini-adr.md`, `@backend/app/main.py`, `@backend/app/models.py`, and `@frontend/index.html`. Generate a frontend implementation plan. Do not apply code changes. Present the changes as a list of tasks in table form.                                                                                                                                                    |
