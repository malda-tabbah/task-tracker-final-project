## Null-title PATCH defect — briefing of changes

These prompts (12–14) produced a code fix for the reviewer finding that `PATCH /tasks/{id}` with `{"title": null}` returned HTTP 500.

**Root cause.** `TaskUpdate.title` is `Optional[str] = None`. The title validator returned `None` when the value was null, so request validation succeeded. `storage.update_task` then used `model_dump(exclude_unset=True)`, which still includes an explicitly supplied null. That `None` overwrote the stored title. Building `TaskResponse` (required `title: str`) raised an unhandled Pydantic `ValidationError` inside storage, which FastAPI surfaced as 500 instead of 422.

**Code change.** In `backend/app/models.py`, `TaskUpdate.validate_title` now raises `ValueError("title cannot be blank")` when `title` is `None`. Omitted `title` is unchanged: Pydantic v2 does not run this validator on the default, so a partial PATCH without `title` still returns 200.

**Tests.** Three cases were added to `backend/tests/test_tasks.py`:

- explicit JSON null (`{"title": null}`) → 422, stored title unchanged
- whitespace-only title → 422, stored title unchanged
- empty string title → 422, stored title unchanged
